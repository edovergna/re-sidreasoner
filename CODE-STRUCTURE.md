## Code Structure

The repository is organized by **experiment suite**, mirroring `docs/`. The five
suites are:

| Suite | Research question |
|-------|-------------------|
| `reproduction` | RQ1 — reproduce the original SIDReasoner paper trends. |
| `components`   | RQ2 — component ablations (which pipeline pieces matter). |
| `grpo`         | RQ3 — sensitivity to GRPO reward formulation. |
| `model_size`   | RQ4 — effect of backbone scale on behavior. |
| `diversity`    | RQ5 — item-side exposure diversity. |

Shared code lives under `common/`. `grpo` is wrapper-native
(configs + jobs + `src/grpo`). The `components` (RQ2), `diversity` (RQ5 item-side),
`model_size` (RQ4) and `reproduction` (RQ1) experiment code lives **inside the
SIDReasoner submodule** — under
`baselines/repos/SIDReasoner/final_scripts/{rq2_components,rq5_diversity,rq4_model_size,rq1_reproduction}/`
plus `utils/` (analysis/plotting/upload helpers), `evaluate_Qwen3_strict_no_think.py`,
and the modified `calc.py` / `sft_reasoning_activation.py` — because those scripts call
the submodule's `split.py`/`merge.py`/`evaluate_Qwen3_think.py` directly. They are
materialised via `patches/common/sidreasoner-local.patch`. Suite documentation lives
in `docs/`. `model_size`/`reproduction` are
CLI-flag-configured inside their launch scripts (no YAML), and their `results/` are
generated by the collect/plot steps at run time.

- `README.md`: Overview of the project.
- `baselines`: Original baseline repositories and the adapters that expose a
  uniform interface to them (shared across all suites — not suite-split).
    - `repos`: Original baseline repos (git submodules).
    - `adapters`: Thin wrappers; e.g. `sid_reasoner.py` maps our YAML config
      schema to each SIDReasoner training/eval stage.
- `configs`: YAML experiment configs. `configs/grpo/<variant>/<dataset>.yaml`.
  Each config's `paths.output_root`/`reward_fn` are repo-relative.
- `data`: Datasets (shared). `raw/ processed/ enriched/`, one subfolder per dataset.
- `scripts`: Executable entry points.
    - `common/`: shared across suites — `eval/evaluate.py`, `train/train_pipeline.py`,
      `data_prep/`, `analysis/`, `apply_submodule_patch.sh`.
- `src`: Importable library code (imported as `src.<suite>.*` / `src.common.*`).
    - `common/`: shared library (`paths.py` with `find_repo_root()`,
      `training/`, `evaluation/`; the latter two are placeholders).
    - `grpo/`: `reward_variants.py` (A0–A3 reward classes) + `reward_shims/`
      (verl entry-points, one per variant).

- `tests`:
    - `common/smoke/`: config-path + dry-run smoke tests (harness-level).
    - `grpo/`: `test_reward_variants.py`.
    - `diversity/`: `test_full_catalog_gini.py`.
- `jobs`: Slurm job files.
    - `common/`: smoke/submit wrappers, dataset/model downloads, `setup_env.sh`.
    - `grpo/`: `reward_sweep.job`, `reward_eval.job`.
    - `outputs/`: `.out`/`.err` from cluster jobs (git-ignored; not suite-split).
- `results`: Experiment outputs (metrics, prediction files), mirroring `configs/`.
- `patches`: Local submodule modifications kept out of the submodule.
  `patches/common/sidreasoner-local.patch`.
- `docs`: Per-suite documentation (`docs/<suite>/`).

### Conventions
- **Repo-root resolution is depth-independent**: scripts/tests find the root by
  walking up for the sentinel (`.gitmodules` + `baselines/`) via
  `src/common/paths.find_repo_root()` (or an inlined walker in entry scripts that
  run before `src` is importable). This locates the root independently of script depth; config paths still resolve from the working directory.
- **`model_size` uses an underscore everywhere** (incl. `docs/`) because `src/`
  is imported as `src.<suite>` and Python module paths cannot contain hyphens.
